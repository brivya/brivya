# Security Policy

Security is a core design requirement for Brivya because Business Agents may trigger real business actions.

## Reporting a vulnerability

Please do **not** open a public GitHub issue for suspected security vulnerabilities.

Until a dedicated security mailbox is published, contact the Brivya maintainers privately through the security contact method listed in the relevant repository.

When reporting, include:

- affected component and version;
- reproduction steps;
- expected and actual behavior;
- potential impact;
- any known workaround.

## Scope

Security-sensitive areas include:

- authentication and authorization;
- capability execution;
- policy and approval bypass;
- secrets handling;
- tenant isolation;
- transaction integrity;
- connector credentials;
- audit-log integrity;
- remote code execution or injection.

## Disclosure

Please allow maintainers a reasonable period to investigate and remediate before public disclosure.
