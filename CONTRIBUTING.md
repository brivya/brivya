# Contributing to Brivya

Thank you for helping build open infrastructure for the Agentic Business Web.

## Before contributing

For substantial changes, open an issue or discussion first so the problem, scope and compatibility implications can be agreed before implementation.

## Development principles

Contributions should preserve:

- protocol neutrality;
- model neutrality;
- typed business capabilities;
- explicit policy boundaries;
- auditable execution;
- backwards-compatible evolution where practical.

## Pull requests

A good pull request should include:

- a clear problem statement;
- the proposed behavior;
- tests for behavior changes;
- documentation for public APIs;
- migration notes for breaking changes.

Keep pull requests focused. Avoid combining unrelated refactors and product changes.

## Security

Do not submit secrets, credentials, customer data or vulnerability details in public issues or pull requests. Follow `SECURITY.md` for security reports.
